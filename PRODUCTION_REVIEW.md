# Подготовка Linux и результаты ревью

Исправления:
- Продажа проверяет права sales на уровне Spring method security во всех перегрузках.
- Продажа, приемка, инвентаризация, редактирование чеков и выполнение доставок используют транзакции и PESSIMISTIC_WRITE; товары блокируются по ID.
- Добавлен Product.version и проверка версии при сохранении карточки. Старая форма не перезапишет остаток после продажи/приемки. Hibernate добавляет version с default 0 для существующих строк.
- Проверены null в поиске альтернатив, заметках, датах отчетов, стоимости закупки и печати чека; добавлена валидация значений карточки на сервере.
- Учетные записи перенесены из памяти в JDBC users/authorities. BCrypt остается; изменение пароля и аудит включены в транзакцию. Стандартные пароли удалены.
- Vaadin productionMode=true и build-frontend включены в обычный mvn clean package. Явно настроен процессор Lombok для сборки новыми JDK с release 17.
- H2 console отключена; файловая H2 и ddl-auto=update сохранены. Логи: logs/application.log, 10MB на файл, 30 дней, суммарно до 1GB архивов.
- Автозаполнение демонстрационными продажами, долгами и каталогом выключено. Для явного запуска нужны app.demo-data.enabled=true и дополнительные параметры генерации/сброса.
- GlobalExceptionHandler уже скрывает технические ошибки; полный стек пишет в консоль и ErrorLog отдельной REQUIRES_NEW транзакцией. Продажи, приемка, инвентаризация и изменения цен уже пишут AuditLog в транзакции операции.

## Развертывание

1. Сохранить проверенную резервную копию существующей БД. Первое обновление с ddl-auto=update сначала выполнить на копии, проверить товары, чеки и остатки.
2. Использовать Java 21 (сборка проверяется этой версией, целевой байткод Java 17). Собрать mvn clean package. На машине сборки нужны Maven, доступ к Maven/npm и Node для фронтенда; серверу запуска нужен JAR и Java.
3. Запускать от отдельного непривилегированного пользователя с постоянной WorkingDirectory, например /opt/sklad. Каталоги data, backups и logs должны быть доступны ему на запись. JAR: target/vse-skhoditsya-0.0.1-SNAPSHOT.jar.
4. Перед первым запуском задать APP_BOOTSTRAP_ADMIN_PASSWORD. При необходимости также APP_BOOTSTRAP_SELLER_PASSWORD и APP_BOOTSTRAP_LOADER_PASSWORD. Минимум 12 символов, максимум 72 байта UTF-8. Учетные записи создаются только если отсутствуют; повторный запуск не сбрасывает пароль. Старые пароли из памяти восстановить невозможно. После создания учетных записей убрать bootstrap-пароли из окружения.
5. В защищенном EnvironmentFile службы задать SPRING_DATASOURCE_PASSWORD и при необходимости SPRING_DATASOURCE_URL=jdbc:h2:file:/opt/sklad/data/sklad_db;DB_CLOSE_ON_EXIT=FALSE. Для существующей БД указать ее действующий пароль; изменение настройки само по себе не меняет пароль существующей H2.
6. Запуск: java -jar /opt/sklad/vse-skhoditsya-0.0.1-SNAPSHOT.jar. В systemd задать User, WorkingDirectory, EnvironmentFile, Restart=on-failure. Секретный файл доступен только root/пользователю службы.
7. За HTTPS reverse proxy задать SERVER_ADDRESS=127.0.0.1, SERVER_SERVLET_SESSION_COOKIE_SECURE=true, SERVER_FORWARD_HEADERS_STRATEGY=native. Прокси должен заменять клиентские Forwarded/X-Forwarded заголовки и поддерживать WebSocket. Публичный доступ только через HTTPS.
8. BACKUP_ZONE=Asia/Yekaterinburg задает время ночного бэкапа. Копировать архивы вне сервера; проверять восстановление. Файловая H2 рассчитана здесь на один процесс приложения, несколько продавцов работают через него.

## Границы проверки

Автотесты проверяют гонку двух продаж последней единицы, отказ сохранения устаревшего товара, запрет всех перегрузок продажи для роли без прав и сохранение BCrypt-пароля при пересоздании менеджера.
Не проводились нагрузочные испытания Linux, полноценные браузерные сценарии всех экранов и сверка всех транзитивных зависимостей с актуальной базой CVE. Устаревающие StreamResource API отмечены компилятором; они пока не мешают сборке. MySQL-драйвер оставлен: в проекте предусмотрен переход на MySQL, однако встроенный backup работает только с H2.

Документация Vaadin: https://vaadin.com/docs/latest/building-apps/production/build и https://vaadin.com/docs/latest/flow/security/vaadin-security-configurer

Результат проверки: mvn clean package — BUILD SUCCESS, 4 теста без ошибок. JAR запущен на временной H2: Vaadin production mode подтвержден логом. HTTP без авторизации: /login доступен; /, /sales, /products, /settings, /reports, /h2-console и /print-receipt/1 проверены на отказ/перенаправление. Тестовый процесс остановлен.
