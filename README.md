# Всё сходится!

## Новый прайс и тестовая история

`price.xlsx` содержит колонки «Наименование», «Цена продажи», «Остаток». Импорт находит их по заголовкам, в том числе при наличии пустых колонок слева. Закупочная цена рассчитывается как 70% цены продажи.

Для разрешённой однократной замены каталога и истории используйте `mvn spring-boot:run -Dspring-boot.run.arguments="--app.demo-data.reset=true"`. Перед таким обновлением нужен бэкап. По умолчанию `app.demo-data.reset=false`, поэтому существующие данные без этого параметра сохраняются.

На пустой базе создаются 25 тестовых поставок, до 125 продаж за последние 30 дней и три тестовых сотрудника со сменами текущего месяца. Продажи без достаточного остатка пропускаются. `app.demo-data.generate=false` отключает генерацию истории.

Завершённый импорт фиксируется в `demo_data_runs`: повторные запуски, даже с параметром reset, не очищают и не дублируют этот набор. Пользователи, права, контакты, сотрудники и прежние смены сохраняются. Существующие доставки переносятся на новые карточки товаров; если товар не удаётся однозначно сопоставить, обновление откатывается.

Стартовое веб-приложение на Java 17, Spring Boot 3.5.7 и Vaadin 24.9.4. Для локальной разработки используется встроенная база H2 в памяти.

## Запуск

1. Установите JDK 17 и Maven 3.6.3 или новее. Укажите JDK 17 в `JAVA_HOME` и в настройках Maven/Project SDK в IntelliJ IDEA. Импортируйте проект через `pom.xml`.
2. Отдельный сервер БД не требуется. H2 создается при запуске: JDBC URL `jdbc:h2:mem:sklad_db`, пользователь `sa`, пароль пустой. Данные хранятся в памяти и удаляются при остановке приложения. Настройки MySQL сохранены в `application.properties` в комментариях.

3. Из корня проекта выполните:

   ```shell
   mvn spring-boot:run
   ```

4. Production: см. PRODUCTION_REVIEW.md. Стандартные пароли удалены; перед первым запуском задайте APP_BOOTSTRAP_ADMIN_PASSWORD.

Можно также запустить `SkladApplication.main()` из IntelliJ IDEA. Для проверки компиляции выполните `mvn compile`.

## Поведение

Все рабочие страницы требуют входа; `/login` доступен без авторизации. Пароли пользователей хранятся в памяти как BCrypt-хеши. Обе роли имеют доступ ко всем разделам. «Товары» открывает заголовок «Товары и услуги»; остальные разделы пока содержат заглушки.

Vaadin настроен на режим разработки: в Maven-плагине явно задано `productionMode=false`, выполняется только `prepare-frontend`. Цель `build-frontend` отсутствует, production-бандл не собирается. При первом запуске Vaadin может загрузить Node.js и зависимости интерфейса, поэтому нужен доступ в интернет.

Hibernate настроен на `spring.jpa.hibernate.ddl-auto=update`. Таблицы будут создаваться и обновляться после добавления JPA-сущностей; в стартовом проекте сущностей пока нет.

## Резервное копирование H2

При старте создается каталог `backups/` относительно рабочей директории процесса, рядом с относительным каталогом `data/`. На Linux при запуске через systemd задайте `WorkingDirectory` каталогом приложения и предоставьте пользователю службы право записи в него.

Пока приложение запущено, `BackupService` ежедневно в 02:00 выполняет H2 `BACKUP TO`. По умолчанию используется часовой пояс JVM/сервера; настройка `backup.zone` позволяет явно указать часовой пояс, например `Asia/Yekaterinburg`.

Ручной запуск: ADMIN → «Настройки» → «Система» → «Создать бэкап сейчас». Архивы имеют имена `backup_YYYY-MM-DD_HH-mm.zip`; повторные запуски в одну минуту получают числовой суффикс. Перед публикацией проверяется содержимое ZIP. После успешного создания удаляются только архивы этого формата с временем изменения старше 30 дней. Ошибки записываются в журнал ошибок, успешные операции — в аудит.

Эти архивы содержат файловую базу H2. Перед восстановлением базы остановите основное приложение. Для другого типа СУБД требуется отдельный механизм резервного копирования.
