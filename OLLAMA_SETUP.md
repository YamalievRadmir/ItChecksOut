# Ollama: настройка чата

В приложении есть чат по кнопке в левом нижнем углу. Сервис использует POST /api/generate, stream=false, модель gemma3:12b. Перед каждым вопросом загружаются все статьи справочника животных, включая новые и старые поля. Вопросы независимые: история показывается в виджете, но предыдущая переписка модели не отправляется.

В /srv/sklad/.env добавьте (готовый фрагмент в .env.example):

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=gemma3:12b
```

Затем на Ubuntu:

```bash
ollama list
# Только если нужной модели еще нет:
ollama pull gemma3:12b
curl --fail http://127.0.0.1:11434/api/tags
sudo systemctl restart sklad
```

Можно выбрать установленную qwen3:14b через OLLAMA_MODEL=qwen3:14b.

Файл .env читается systemd через EnvironmentFile; обычный java -jar автоматически его не читает. Значения по умолчанию уже установлены в application.properties.
Для локального Windows-приложения 127.0.0.1 — Windows-компьютер, а не Ubuntu. Для проверки через серверный Ollama без публикации порта можно открыть SSH-туннель из PowerShell:

```powershell
ssh -N -L 11434:127.0.0.1:11434 radmir@192.168.0.243
```

Оставьте окно открытым и задайте вопрос в чате http://localhost:8081. На Ubuntu, где приложение и Ollama работают на одном хосте, туннель не нужен.

Чат выполняет запросы в фоновом пуле (2 задачи, очередь до 4), обновляет интерфейс через UI.access и Vaadin Push. Подключение ограничено 5 секундами, ожидание ответа — 180 секундами. При недоступности модели пользователь получает понятное сообщение, техническая ошибка сохраняется обычным обработчиком в ErrorLog и серверный журнал. Ответ выводится как текст, без исполнения HTML.
Nginx должен сохранять настроенное ранее проксирование WebSocket.

Документация: https://github.com/ollama/ollama/blob/main/docs/api.md и https://vaadin.com/docs/latest/building-apps/server-push/updates
